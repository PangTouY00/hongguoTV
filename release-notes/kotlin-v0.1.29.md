# 红果 TV 0.1.29

版本：`versionName 0.1.29` / `versionCode 70`，支持 Android 6.0 及以上（minSdk 23）。覆盖安装即可，账号、收藏、观看进度与本机缓存记录都保留。

这一版只修一件事：0.1.28 之后**仍然所有集播不了**——首页、榜单、详情、搜索都正常，取址一律回 `HTTP 200 + 0 字节`。根因不在签名头族（那一族上一版已经改对），而在 medusa 明文里一个被写错的字段值。

## 一、真正的原因：medusa 明文的第 21 个字段

v5 签名里的 `x-medusa` 是一段 protobuf 明文，经过封装与加密后发出去。它的第 21 个字段我们此前写的是 **377**，正确的值是 **312**（原始 protobuf 数值 624，即 zigzag 有符号值 312）。

这个字段填错不会让请求报错——它仍然是一个格式完全合法的 medusa，服务端只是不给数据：`HTTP 200`，正文 0 字节。所以从界面和日志上看，它和「服务端这一时段不放行」长得一模一样，这也是它难找的原因。

上游 N3urda/hongguoTV 的 PR #107（2026-11-23 合并，随其 0.16.14 发布）用「固定 URL、固定 gzip 正文、固定匿名身份、固定时间戳与传输，只替换 medusa 的指定字段」的逐字段 A/B 把范围收敛到这一项：把成功签名的这一项换成 377 就回 200 + 0 字节，把失败签名的这一项换成 312 就取回模型，重复请求仍然成功。其余有差异的字段（第 13 字段尾部四字节、第 10、15、23、24 字段）单独替换都不影响结果。官方 App 7.4.5.32 与独立 SDK 在这两个样本上给出的原始 protobuf 数值都是 624。

这台手机上用同一份新注册身份复现，同一个签名器只换这一个字段，三个样本各跑两路：

| 第 21 字段 | 三个样本的结果 |
| --- | --- |
| 377（0.1.28 的写法） | 全部 HTTP 200 + 0 字节 |
| 312 | 全部 `code:0`，各五档清晰度，`main_url` 含 1920×1080 |

带与不带设备 Cookie 结果一致。

## 二、改了什么

- [`V5Constants.field21 = 312`](kotlin-tv/core/src/main/kotlin/com/hongguotv/core/V5Constants.kt)，[`Signer.medusaV5`](kotlin-tv/core/src/main/kotlin/com/hongguotv/core/Signer.kt) 使用它。真正改变线上请求的只有这一行。
- `Signer` 多了一个带默认值的 `field21` 参数，只为了让对照探针能在同一份身份下按两个值各发一次；生产调用不传，取 `V5Constants.field21`。
- 接上上游随 PR 给出的完整签名固定向量 `core/src/test/resources/signing-v5-playback-312.json` 与一条回归测试：312 下与向量逐字节一致，换回 377 则 `x-medusa` 不一致。它同时锁住「改对了」和「没改多」——证明这次移植没有连带改动别的字段或封装。
- 新增对照工具 [`tools/probes/Field21Probe.kt`](kotlin-tv/tools/probes/Field21Probe.kt)：先离线对拍（对不上就不许开始试网络），再在同一份新注册身份、同一固定时间戳与随机量下只换这一个字段做联网 A/B。本机不用 Gradle 就能跑，用法写在文件头上。
- 文档更正：[`PLAYBACK_DIAGNOSIS.md`](kotlin-tv/PLAYBACK_DIAGNOSIS.md) 的 A 节里把「全空时签名也不是变量」这句话的范围收窄，改成**换头族不是变量，换头里的具体字段是变量**——签名对照要按字段做，不能只按头族做；四路都带 v5 三头却仍然全空时，改跑 `Field21Probe.kt`。[`PLAYBACK_V5.md`](kotlin-tv/PLAYBACK_V5.md) 记下这次更正与两组对照。

## 验证

- core 单元测试通过，包含新加的固定向量回归。
- 本机 `Field21Probe`：377 三样本全空，312 三样本 `code:0`、各五档含 1920×1080，并取到真实媒体地址。用的正是之前一直取不到的那三集。
- GitHub Actions 运行 `:core:test`、`:app:testDebugUnitTest`、`:app:lintDebug`、`:app:assembleDebug`、`:app:assembleRelease`，全部通过后才发布本包。
- **真机播放尚未验收。** 本机验证到的程度是「取到五档清晰度与真实 `main_url`」，画面能不能出来需要装机确认。

## 怎么验证

1. 播之前播不了的这几集：《全球死考》第六季第 153 集、《谁让这个文盲修仙的》第七季第 1 集、《和离后我带女儿横扫魔域》第三季完结篇第 1 集。这三个 id 在本机已经能取到五档含 1920×1080。
2. 若仍失败，打开设置页「诊断日志」复制出来发我。现在那里面会写明这一轮取到了哪几档、或者服务端回了什么状态码和字节数，能直接分出来是取址问题还是解码问题。
