# 红果 TV 0.1.22

版本：`versionName 0.1.22` / `versionCode 63`，支持 Android 6.0 及以上（minSdk 23）。覆盖安装即可，账号、收藏、观看进度与本机缓存记录都保留。

这一版只做一件事：把弹窗的高度收到贴着内容。上一版界面做完之后装机反馈是「弹窗大小不合适」——两三行的面板撑满整屏，多出来的全是空白。

## 问题在哪

Material 主题给对话框的是固定尺寸：横屏取屏高的 90%，竖屏取 70%。实机量过：账号页和「版本与更新」的面板是 1560×972，正好是 1080p 横屏的 65% 宽和 90% 高，而里面只有三五行正文。

第一版改法是 `setLayout(width, WRAP_CONTENT)`，装机无效。uiautomator 量到窗口还是 928 高（只是被兜底上限裁过一截），而真正装着正文的那层只有 564。对话框的 decor 是 `match_parent` 的 FrameLayout，窗口给 `wrap_content` 系统不认。

第二版改成显示之后去量内容层（`android.R.id.content` 的第一个子节点）的实际高度，按具体像素收窗口。这对自定义 View 那类面板有效，装机也确认收住了。但清晰度、倍速这类还是不行，原因有两条：一是它们走的是原生 `setSingleChoiceItems`，Material 的 alert 布局把装列表那一截写成 `layout_weight="1"`，窗口给固定高度时它被拉满，于是「内容层高度」量出来就是窗口高度本身，收缩条件天然不成立；二是这几处当时根本没接上收缩逻辑，在 `MainActivity` 里直接 `.show()` 就出去了。

## 这一版怎么做

两类对话框分开处理，共用一个入口。

**自定义 View 的那类**（红果账号、版本与更新、云端继续观看、扫码登录、跳转集数、手机输入剧名、备份与恢复）沿用上一版的做法：显示之后量内容层的实际高度，按具体像素设窗口高度。

**选项列表的那类**（全局默认清晰度、全局默认倍速、播放设置、弹幕设置）改成按列表真正需要的高度收：先把带 weight 的祖先层放开（weight 归零、高度改成 wrap），列表高度按已经显示出来的每一项相加，连内边距和分隔线一起算，窗口按差值收缩。标题和按钮那两截不动，按钮自然跟上来。只有全部选项都在屏上时才收——列表没显示全时按已显示的算会把没测到的项漏掉，那种情况宁可不动。

顺带三处：

- 开源许可、剧评长文这两处原生对话框以前没接收缩逻辑，现在接上。
- 选项面板的窄尺寸分支和选集网格那两处 `setLayout(..., WRAP_CONTENT)` 改成只设宽度。高度给 `wrap_content` 系统不认（第一版实测过），留着只会盖掉收缩的结果。
- 收缩前读窗口宽度挪到布局完成之后。以前是在调用收缩之前读的，如果调用方在之后才把窄尺寸设上去，读到的会是主题的默认宽度。

上限仍是屏高的 86%：正文真的高过屏幕时走上限，让底部按钮留在屏内；另有一条 140dp 的下限兜底，避免异常情况下收到看不见。

## 怎么验证

装上后按遥控器走一遍：账号页、「版本与更新」这类三五行正文的面板应该贴着内容收，不留大片空白；「全局默认清晰度」「全局默认倍速」这类选项面板的高度应该等于标题加选项再加一行按钮，「取消」紧跟在选项下面，不在半屏之外；云端继续观看、扫码登录这类长内容面板应在上限处停住，内容能滚、按钮不被裁掉。

需要真机确认的：短面板收到多小算合适，三五行正文收完之后会不会显得太扁；选项列表收完之后焦点上下走位是否还顺；有没有哪个面板被收过头、把内容或按钮裁掉了。看到留白、太扁、或者裁掉了东西，请反馈。

## 安装与更新

- 下载本页附件 `hongguotv-kotlin-0.1.22-android6.apk`，覆盖安装。
- App 内「检查更新」读的是本仓库标记为 Latest 的正式 Release，附件同时带 `update.json`（含包名、版本、大小与 sha256）。
- 这一版没有改动账号、收藏、观看进度与缓存的存储格式，升级后直接沿用。
