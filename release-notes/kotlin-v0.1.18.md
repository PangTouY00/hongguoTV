# 红果 TV 0.1.18 更新说明

这一版只改一件事：取播放地址被服务端拒绝时，客户端换一份设备身份再重读。上一版把签名头补上以后，取址大部分时候正常了，但还留着一个间歇性的毛病——有些集会一直打不开，报「播放接口暂不可用（错误码 110001）」，或者取到空响应。版本号 versionName 0.1.18 / versionCode 59。这一版仍然只发布 Android 6.0 及以上的包。

## 剩下的失败长什么样

补上签名之后，两种失败同时存在：

| 接口 | 表现 |
| --- | --- |
| `GET /reading/bookapi/video_tab/multi_video_model/v1/` | 有时回 `HTTP 200` + 0 字节，有时回 `code 110001` |
| `POST /novel/player/multi_video_model/v1/`（回退） | 带签名时回 `code 110001` |

八个参数逐项核对过，一个都不缺；换域名、换 UA、换出口 IP、换 Cookie 都不改变结果。所以这不是请求写错了，是服务端在那一刻不给这份设备身份下发清晰度。

## 关键的一条：同一份身份会一直失败

同一台设备、同一集连续重读，失败会连着来；把这份匿名注册身份丢掉、重新注册一份，请求往往立刻就放行。也就是说服务端拒绝的是「这份身份在这一段时间里的请求」，不是这个请求本身。上一版的处理是换一张新的请求票据重读两次，身份不变，正好卡在这一点上——同一份身份重读两次通常还是失败。

这一版按这个结论改：重读的时候连身份一起换。

## 改了什么

- 取址的重读从 2 轮增到 4 轮，间隔按轮递增：0.7 秒、1.4 秒、2.1 秒。
- 每轮重读前先丢掉当前注册身份（`PlaybackDeviceSession.invalidate()`），下一次请求重新注册一份，连 `cdid` 一起换掉。
- `110001` 单独归成一类可重试的暂时拒绝（`PlaybackRejectedException`），新接口和回退接口共用同一套错误码分类，不再一处认一处不认。
- 四轮都被拒时，报出真实错误码。之前走到回退接口拿不到数据时会报成「播放信息为空」，把服务端给的码丢掉了；现在保留。

## 没有改的部分

签名算法、请求参数、清晰度选择与降级、缓存落盘、断点续传、离线播放、登录、投屏、弹幕都没动。已经下载到本机的剧集不受影响。注册接口本身没变，只是取址失败时多注册一次。

## 自动化检查

`:core:test` 272 项通过（分支 CI run 42228636368，调试包 `build-fix-playback-ladder-retry-b782e7f`）。新增两个测试锁住两件事：连续取到空正文时，重读必须换过注册身份；两个接口一起回 110001 时，最终报出的必须是 110001，不能退化成「播放信息为空」。

## 安装

Android 6.0 及以上下载 `hongguotv-kotlin-0.1.18-android6.apk`，覆盖安装即可，收藏、观看进度与本机缓存记录保留。

装机先看之前常报 110001 的那几集：现在应该是在一两秒内出画面，这期间它在换身份重读，最多四轮。如果四轮都被拒，会明确报「播放接口暂不可用（错误码 110001）」——把出现的时间、剧集和当时的网络情况告诉我，说明这条链路上还有别的触发条件没找到。
