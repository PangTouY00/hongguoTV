# 红果 TV 0.1.26 更新摘要

这一版改两件事：播完之后该接着看哪一季，以及起播前那一笔白付的重复请求。

**已播完面板。** 原来同一系列的每一季都写成「下一季」，三季并列时看不出该接着看哪一部。现在先算出当前这一部是第几季（标题没有季号就当第一部，「第2季」「第二季」都按读到的算），只把季号正好是当前 + 1 的那一条标出来，写成「接着看 · 第2季 · 剧名」，其余同系列的季写成「其他季 · 第3季 · 剧名」，并对前者加粗、用强调色。隔了一季的、季号读不到的、还在待上线那一组的都不标。区分同时走文字、加粗和颜色三样，因为焦点态会换底色、电视上色觉也不同，只靠颜色分不出来。

**取址。** 一集的所有清晰度都是厂商私有编码时，取址会在 v5 之外再发一条要 h264 兼容档的请求。实机五集连播里它五次全回 HTTP 200 + 0 字节，一次 0.9～1.8 秒，而最终播通的恰恰是 v5 给的那份 1080P 私有编码——首页试播的取址耗时里它占 32%～47%，正式播放那次占取址总耗时的 68%。现在同一件事只问一次：这一集用的私有编码在这台设备上真渲染出过首帧，或者这条请求刚刚失败过（进程内 10 分钟冷却），都不再重复问；跳过时日志写明是哪一种情况。记的是这一集实际用的那一种编码，不是接口下发的某一档，也不是系统报出来的解码能力。冷却过期后、或换到一种这台设备没试过的编码时，照旧再问。选哪一档的规则没变。

取址成功那一行日志改成写实际成功的那条请求带没带账号 Cookie、清晰度来自哪条接口。此前它照轮次写「带」，而真正成功的是 v5 那条，它强制不带任何 Cookie。

起播的缓冲门槛从 1000ms 降到 500ms，与首页试播同一个值；播放中途重新缓冲的门槛保持 2000ms 不变。失败重试的节奏没动。

**没动的。** 首段读 256KB 没砍——那些字节除了索引全是首帧要用的样本数据，砍了只是把等待挪到播放器。首帧那 1.7 秒主要是当时链路吞吐只有 100～150 KB/s，代码解决不了。首页推荐接口 2～4.7 秒是另一件事，这版没碰。

## 怎么验证

播完一部多季的剧，看面板里该接着看的那一季有没有被单独标出来。连播两集以上，设置 → 诊断日志 → 复制，看第二集起有没有「本机已实测这种编码能播，不再要兼容档」或「兼容请求刚失败过，这一轮不再问」——有这一行，取址就该短 1 秒上下。起播门槛降到 500ms 后如果更容易起播即卡，这一项会单独退回 1000ms。

新增 12 项 core 单测覆盖这两处。覆盖安装即可，账号、收藏、观看进度与本机缓存记录都保留。
