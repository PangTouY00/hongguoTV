# 红果 TV 0.1.9 更新说明

本次更新处理两件事：弹幕和评论里的表情标签现在能显示成表情图片；手机号登录失败时给出准确原因，并把人引到当前真正可用的扫码登录。

## 弹幕与评论显示红果的表情标签

红果的弹幕和评论里，表情是以文字标签下发的，例如 `[爱慕]`。之前只有少数通用写法带插画，其余标签在画面上就是一串方括号文字。

这次补上红果弹幕表情面板里的 11 个标签：爱慕、爽、奸笑、震惊、什么、尬笑、舔屏、吃瓜、探究、送花、笑。滚动弹幕仍按标签切成文字段与图片段，图片按当前弹幕字号缩放并与文字共用一条基线，整行宽度按切段后的实际宽度计算；评论面板里的同一标签也换成图片。未识别的标签保留原文，不会丢字。

插画继续用 Microsoft Fluent Emoji（MIT，许可随包 `assets/comment_emoji/LICENSE.txt` 分发），新增 10 张 3D 风格图，与已有的 16 张同一套风格。素材读取同时支持 WebP 与 PNG 两种容器。两点如实说明：这些是通用替代表情，不是红果官方贴图；Fluent 表情集里没有 U+1F605，「尬笑」改用 U+1F603（笑中带汗）的插画，「酸」这个标签没有对应插画，仍按原文显示。

## 手机号登录：说清楚平台边界，不再让人反复试

现象是短信能收到，提交验证码却报「平台拒绝本次登录会话（错误码 1）」。

复核上游的抓包记录并重新实测两条通道后确认，原因在平台侧：`aid=8662` 的 passport 手机号流程是给已登录账号**绑手机**用的，`validate_code`、`sms_login` 等四个验码端点对第三方客户端一律回 `error_code 1`（会话不成立），与是否带 `mobile_ticket`、用 GET 还是 POST 无关；官网通道的手机号发码又被滑块验证（`1105`）挡住。电视端目前真正可用的登录方式是扫码。

据此调整：

- 验码不再在第一个端点被拒时就判定登录不可用，四个端点全部试完；只有「验证码本身不对」（1102）和「平台要求滑块」（1105）会提前返回。
- 失败提示改用平台回给的原话，并明确引导改用扫码登录；账号页的手机号入口标注「平台暂不签发会话」，输入手机号时也会先说明这条边界，避免在电视上反复重发验证码。
- 扫码登录本次实测正常（二维码与轮询都正常返回），仍是推荐路径。

## 自动更新：放行 GitHub 的另一个资产域名

GitHub 对 release 附件可能改用 `release-assets.githubusercontent.com` 下发。之前只放行 `objects.githubusercontent.com`，遇到这种资产会被域名白名单拦下，报「更新下载地址不受支持」。现在两个资产域名都放行，检查更新、读取清单和下载仍然先走 `gh-proxy.com` 镜像、失败时回退 GitHub 直连。

## 兼容与验证

- 仍是单一 APK：minSdk 23（Android 6.0 及以上），versionName 0.1.9 / versionCode 50，包名与签名与 0.1.8 一致。
- CI 跑 `:core:test`、`:app:testDebugUnitTest`、`:app:lintDebug`、`:app:assembleDebug`。Robolectric 在 API 23 与 API 26 上验证：这 11 个表情标签都能切成文字段与图片段并取到插画；登录被拒时四个端点都被尝试、错误码与扫码引导都在，会话判定失效后同一验证码不能再提交。
- 弹幕的实际观感、登录提示在电视上的呈现需要装机确认。
