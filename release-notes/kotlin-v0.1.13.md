# 红果 TV 0.1.13 更新说明

这一版加离线缓存：短剧可以单集或整部存到本地，存下来的集不需要网络也能播。版本号 versionName 0.1.13 / versionCode 54。

## 在哪里缓存

- 选集面板新增「缓存本集」「缓存全部」。
- 剧集详情页的次要操作行新增「缓存全部 N 集」，按钮文字跟着状态走（「已缓存 x 集 · 缓存全部」「已全部缓存 · x 集」「缓存中 · 还有 n 集」）。
- 播放页「播放设置 → 缓存管理」：缓存或删除当前这一集、缓存未缓存的全部、清空全部、停止队列，并显示已缓存集数、占用 MB 与剩余空间。
- 一集在缓存里的状态直接画在集数上：`✓` 已缓存、`…` 排队中、百分比、失败。播放界面状态行在清晰度后标注「本地缓存」。

## 缓存里存的是什么

缓存文件存的是播放器实际消费的字节：改写过的容器索引，加已经解开的样本。所以离线播放不需要密钥、不需要再解密、也不需要网络。

缓存键是分集 id 加清晰度，不是播放地址的哈希。播放地址带签名有效期，用地址做键会让同一集反复重下，也没有稳定的「删掉这一集」入口。

文件存在应用自己的外部私有目录，不需要任何存储权限，代价是卸载即清，这一点写在缓存管理里。留出 512 MB 余量，一集放不下时当场拒绝并给出剩余 MB，不会留下永远续不完的半截文件。

## 播放时怎么选

先查本地：命中就直接本地播，不查清晰度阶梯、不发任何请求——签名过期、限流、设备注册这些在线才会出的问题都不存在。缓存档能不能解码仍走同一套 MP4 头校验，判不过就回退在线，由在线那条路去挑这台设备解得了的那一档。

自动连播时，下一集已经在本地就不再预热：本地打开没有取址与首段网络等待，预热反而抢带宽。

## 队列与中断

一次只下载一集，按点下的顺序排队；连续三集都失败就停下整批，不再把整部剧试一遍。

中断（返回、杀进程、连接断开）留下 `.part`，下次点同一集从已写的字节继续；半截文件比这一集还长时不续传，重写。列缓存时只列出元数据声明的字节数与文件实际大小对得上的记录，对不上的当场清掉。

## 验证

- `:core:test` 251 项全过，新增 18 项覆盖落盘与列出、按 1 MiB 分块、断点续传（已写过的字节不再要第二遍，拼出来的文件与一次写完的完全一致）、取消保留进度、半截文件过长时重写、元数据与文件大小不符时当场清掉、多档时取上限内最高的那一档、删除与清空、空间判断。另有一条端到端：按在线播放的方式取字节、落盘、再从缓存不带任何密钥地读回来逐段比对，并确认缓存文件里已经是可解码的索引（`encv`/`sinf` 被还原成 `avc1`）。
- GitHub Actions 运行 `:core:test`、`:app:testDebugUnitTest`、`:app:assembleDebug`、`:app:lintDebug`、`:app:assembleRelease`，核对包名 / versionName / minSdk 后才发布本包。
- 未验证：实际电视上的下载速度、离线播放的连续性与遥控器上的缓存操作手感需要装机验收。缓存下载与正在在线播放的那一集共用带宽，整部剧缓存期间当前播放可能缓冲更慢，这一版没有为它加专门的调度。

## 本次只发布 Android 6.0+ 构建

- 本版只有 `hongguotv-kotlin-0.1.13-android6.apk`（minSdk 23）。
- `android44-support` 那条线没有离线缓存，本次不发布 4.4 包，那条线继续单独验证。
- 包名与签名不变（与 0.1.11 / 0.1.12 同一把 CI 密钥），已装 0.1.12 可直接覆盖安装，本机收藏与观看进度保留。

## 安装

- App 内「设置 → 检查更新」直接升级（读的是本仓库 Releases 里标记 Latest 的正式包）。
- 直连：https://github.com/PangTouY00/hongguoTV/releases/download/kotlin-v0.1.13/hongguotv-kotlin-0.1.13-android6.apk
- 镜像加速：把 `https://github.com/` 换成 `https://gh-proxy.com/https://github.com/`。

装机后如果缓存或离线播放有问题，把屏幕上那行提示原样发我；logcat 搜 `Episode cached` / `Episode cache failed` 能看到每一集的缓存结果与失败原因。
