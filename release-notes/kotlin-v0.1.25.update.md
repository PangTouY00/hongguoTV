# 红果 TV 0.1.25 更新摘要

这一版修的是「所有集都播不了」。

11 月 16 日起取址每一轮都是 HTTP 200 + 0 字节，换注册身份、换 Cookie 都不改变结果，而首页、搜索、榜单全部正常，官方 App 在同一张网络上能播。对照只换签名这一个变量：同一条 path、同一份新注册身份、同一集号、同一 gzip 正文，旧签名回 0 字节，v5 签名回 24345 字节、业务码 0、五档模型齐全——根因是签名协议落后。

改法：播放取址改用 v5 签名协议，签名、常量与合成测试向量取自上游 `N3urda/hongguoTV` 的固定提交并逐字节对拍通过（4 条 AES v5 carrier、32 条 `hashF13`、32 个连续时间戳的签名）。另外发现同一条接口有两种 path 写法，服务端反应不同：带 `player` 那一段的一律回 0 字节，不带的那段、结尾带斜杠的一律回五档模型。所以当前写法没有结果时会当场换另一条再要一次，用的仍是同一份设备身份、同一份正文、同一套签名；业务码非 0 不触发切换。顺带补回 `x-medusa`、`x-helios`，并多试一条 `POST /novel/player/video_model/v1/`。

新增内存诊断日志：设置页「诊断日志」点一下把整份日志复制到剪贴板。取址失败记下状态码、响应字节数与网关 logid，播放失败记下完整原因链，日志不含 Cookie、令牌、账号，可以直接贴出来。

真机验收：v5 请求 1.1 秒回完整模型，五档 360p 到 1080p 齐全；装调试包后可以正常播放，包括只有 `bytevc1` 私有编码的三集——此前「系统播放器解不出厂商私有编码」的判断在这台设备上被推翻。

代价：当前写法真的不给结果时，每次取址多花一次失败请求（约 0.3～1 秒）。日志里「当前取址写法没有结果 → 换 …」紧接着取到，是预期行为。

## 怎么验证

点播放应该直接出清晰度列表。如果播不了，设置 → 诊断日志 → 复制，看取址回的状态码、正文字节数、业务码，这三样决定是哪一类故障。

覆盖安装即可，账号、收藏、观看进度与本机缓存记录都保留。
