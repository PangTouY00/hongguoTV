# 红果 TV 0.1.15 更新说明

这一版主要修在线视频全部播不了：服务端把旧的播放地址接口关了。另外选集面板加了「缓存未看」，断网时已经缓存过的剧也能进得去、播得着。版本号 versionName 0.1.15 / versionCode 56。

## 在线视频播不了：播放接口换了

先说现象。装 0.1.14 的设备从 2026-11-02 起所有在线视频都打不开：首页显示「暂时无法加载 · 内容响应为空」，点开任意一部在线剧都没有画面，只有之前下载到本机的能播。

原因在服务端。旧的播放地址接口 `POST /novel/player/multi_video_model/v1/` 现在对第三方客户端一律返回 HTTP 200、0 字节。换域名（api5-normal-sinfonlineb 和 a）、换 UA、带 Cookie、带完整签名头（x-gorgon / x-ladon / x-argus 等）、带 device_token，结果全都一样。官方 App 已经改用另一个接口：`GET /reading/bookapi/video_tab/multi_video_model/v1/`。同一台注册设备、同一时刻，旧接口 0 字节，新接口 `code=0` 返回完整清晰度。

这一版把播放地址改成优先读新接口，旧接口保留成回退，新接口取不到才用它。新接口对参数要求严格：`video_id`、`video_id_type=0`、`device_level=1`、`need_all_video_definition=1`、`need_mp4_align=0`、`use_os_player=0`、`video_platform=1024`、`source=0`、`from_video_id=`，缺任何一项服务端回 100103。它的响应把播放模型放在 `data.video_model_data[<id>].video_model` 里，是一段 JSON 字符串，解析走和原来同一份代码。两个接口都失败时，报错里写新接口返回的错误码，不再只剩一句「内容响应为空」。遇到 200 空响应，重试前会先清掉半失效的会话 Cookie，不再原样重放被拦的请求。

验证方式：在真机上用注册好的设备身份把整条链跑通——注册 → 详情 → 新接口 → 解析出 1080P H.264 播放地址。

个别剧偶尔仍可能取不到地址，那是服务端按设备身份限流，重试或换一部再切回来即可。

## 选集面板：「缓存未看」

选集面板顶部多一个「缓存未看」按钮，一次把这部剧里没缓存过的未看集全部排进下载队列。缓存失败时写明原因——空间不足、网络断开、这一集没有可缓存的清晰度——失败的那一集可以单独重试，队列继续跑后面的集，不会因为一集失败整批停住。

## 断网时，已缓存的剧进得去

以前进详情页不管本地有没有缓存，都先请求详情接口。断网时这一步直接失败，停在「暂时无法加载，请检查网络后重试」，走不到选集，也就走不到播放——播放那条路径本来就优先读缓存，只是没人能走到它。

现在详情接口失败、而本地恰好有这部剧的缓存时，用缓存元数据拼出剧集列表：能进详情页，能看到哪几集在本地，点开直接播。列表会写明这是离线列表、哪些集没有缓存。

## 没有改的部分

缓存的落盘格式、断点续传、串行队列、离线播放路径与解码校验都没动。播放接口这次只换了取地址这一步，清晰度选择、回退顺序、播放器都不变。

## 自动化检查

`:core:test` 263 项通过，其中新增 `UnwatchedEpisodesTest`：未看且未缓存的集号计算，覆盖全部未看、部分已缓存、全部已缓存三种情况。app 层新增 `CacheQueueTest`（缓存队列失败写明原因、单集重试、队列不停）、`EpisodePanelUnwatchedTest`（「缓存未看」按钮与计数）、`OfflineDetailTest`（详情接口失败时由本地缓存拼出剧集列表、离线标记）。`:app:testDebugUnitTest`、`:app:assembleDebug`、`:app:lintDebug` 全部通过后才发布本次两个包。

## 安装

Android 6.0 及以上下载 `hongguotv-kotlin-0.1.15-android6.apk`，Android 4.4 到 5.x 下载 `hongguotv-kotlin-0.1.15-android44.apk`，覆盖安装即可，记录保留。两个包版本号与标签相同，只是最低系统版本不同。App 内「检查更新」会自动挑本机系统装得上的那个包，不需要自己挑文件。

Android 4.4 这条线自 0.1.12 起在 CI 里构建失败，中断了三个版本，这次一并修好，之后与 Android 6+ 同步发版。
