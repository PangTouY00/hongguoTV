# 红果 TV 0.1.23

版本：`versionName 0.1.23` / `versionCode 64`，支持 Android 6.0 及以上（minSdk 23）。覆盖安装即可，账号、收藏、观看进度与本机缓存记录都保留。

这一版集中修播放取址。上一版发出去之后，装机反馈是「完全无法播放」和「同一部剧有些集能播有些不能」。两次都不是解码问题，logcat 里是取址接口被拒或者回空正文。11 月 9 日到 11 日，服务端的要求改了三次，我们跟着改了三次，每一次都是先把决定变量测清楚再动手。

## 第一件：一份注册身份只放行有限几次取址（11-09）

探针在同一台手机、同一部剧、同一集上测出来：

- 同一份注册身份连试 8 次，全部 HTTP 200 空正文，间隔拉到 4 秒也一样；
- 换一份新注册的身份，第 1~2 次就回 code=0；
- 一份新身份串行取 20 集，只有第 1 集成功，后 19 集全空；
- 同一份身份并发取 8 集，4 成 4 空；
- 冷却 90 秒、180 秒都不改变结果，不是时间窗限流；
- 版本指纹（注册侧 7.3.9.32 对 query 侧 7.1.3.32）与 `from_video_id` 参数做轮转对照各 8 轮，3/8、3/8、3/8、5/8，都在噪声里，不是原因。

结论是服务端按注册身份配额放行取址。首页试播、下一集预热和用户点播共用同一份身份时，先跑掉的那几个请求会把后面那个的配额用光——这就是「有些集能播有些不能」。

改法：`fetchLadder` 每一轮先作废手上这份身份、再取一份新注册的；会话的 cdid 不变，平台仍把它当同一台设备。注册失败并入可重试那一类，不再让一次注册失败直接终止取址。每次尝试的形态写进 logcat 的 `Playback address attempt:`，界面不显示。

## 第二件：取址还要求账号身份（11-09）

你实测「装了上一版反而完全无法播放」，同时确认「登录后可以播，刚才没登录」。接着把变量分开测：

- 设备注册接口正常，连续 5 次全部成功，200~700ms；
- 取址接口对匿名请求每一集都回 code=110001：搜索到的 3 部剧各前 3 集加上之前那集，共 10 个 video_id 全部被拒，旧接口回空正文；
- 换注册身份、只带设备 Cookie、不带任何 Cookie、带额外 sessionid，三种形态各 3 次，结果完全一样；
- 搜索与详情接口用同一套签名照常返回数据，所以不是签名失效，也不是这些剧下架；
- 登录之后同一集立刻能播。

这个接口在「每份注册身份只放行有限几次取址」之外，还多要求一道账号身份。上一版「交替带账号 Cookie」让第一轮必然落空，未登录时更是四轮全部落空，界面上就只剩「准备恢复暂停位置 · 重试 2/3」这种看不出该做什么的提示。

改法：已登录时第一轮就带账号 Cookie，那一轮被拒再退回匿名试一轮，账号凭据失效时不至于整条路都不通；未登录时只试一轮，被服务端拒就报 `PlaybackLoginRequiredException`，播放页显示「播放需要登录红果账号」并给「登录红果」入口，不进自动重试。

## 第三件：服务端开始校验真签名（11-11）

当天所有请求（登录与否、换不换注册身份都一样）一律回 HTTP 200 + 0 字节。同一时刻用主仓库 0.1.30 的取址代码跑同两集，同样全空。主仓库当天 `269c6d8` 已确认根因：服务端开始校验真签名，而我们的 `x-argus` 只是 `base64(时间戳)`，同时又发 `x-gorgon` / `x-helios` / `x-medusa` 这些伪造头，请求被判不可信后直接回空体。设备注册与详情接口不受影响。

照它改了三处：

- 新增 `core/Argus.kt`，`x-argus` / `x-ladon` / `x-gorgon` 的 Kotlin 移植（GPL-3.0-only，源自 fqapp 的 rust 实现，来源声明保留），含自定义 protobuf、Simon 分组加密与 Ladon ARX。
- `playbackRequest()` 按最终 query 用 `PlayerSigner` 重生成签名头，`x-khronos` 与 URL 里的 `_rticket` 同源，占位头一律不再发送。
- 签名器改用这份注册身份构造，并在同一会话里复用。此前 medusa 明文里写死的 device_id 是编译期那份占位身份，和 query 里带的注册 device_id 不是同一对，服务端按身份核对两者；每次请求新建签名器还会让 medusa 里的进程 nonce 与进程启动时间逐次变化。取址也改用官方播放器的请求形态：query 不带 ts，UA 用 PLAYER_UA，版本参数换成播放器那一套（7.3.9.32），参数补上官方 `GetVideoModelRequest` 里的 `from_video_id`。

## 还挡着一层：全档 bytevc2 的集

签名修好后接口有数据了，某些集仍然取不到清晰度：`video_list` 五档的 `video_meta.codec_type` 全是 `bytevc2`，Android 的 MP4 解不出这种视频轨，选流规则把它们全滤掉，结果是「没有电视可播放的清晰度」。官方播放器对这种内容有一条兼容请求 `codec_type=0&force_codec=h264`，补上之后能拿到 h265 的 1080P 与 360P。

这里自己先踩过一次：兼容响应的 `key_seed` 和原响应不是同一份。第一版代码只换了 `video_list`、还拿旧 seed 去解新的 `main_url`，解不开，清晰度列表又变空。改成整份 `data` 都换成兼容响应那一份才通。

## 顺带两处

- 选档不再预判设备能力：给最高一档真解一次，解码失败沿阶梯往下走并重新取址（#30）。按能力预判会误判，真解一次更准，代价是失败时多走一步。
- 播完一集在本地记一笔（`watched-episodes`，每剧至多 2000 集、至多 200 部剧）：选集面板与详情页的分集网格照它标「已看」，底色用灰蓝（`TvStyle.watchedEpisode`），跟「中途停下」的绿色和「没看」的玻璃分开；「缓存未看 N 集」跳过这些集，首页卡片写「已看完 N 集」；删除或清空历史时一并清掉。云端上报的仍然只是「看到第几集」这一条。

## 怎么验证

1. 未登录直接点播放：应该看到「播放需要登录红果账号」和「登录红果」入口，而不是反复「准备恢复播放」。
2. 登录后点之前播不了的集：应该直接出清晰度列表。
3. 连着点几集、连着看下一集：不应该再出现「有些集能播有些不能」。
4. 一集看完回到选集面板：那一集应该是灰蓝的「已看」，「缓存未看 N 集」的计数应把它排除。
5. 只有 bytevc2 档的集：应该能出 h265 的清晰度；真机解不了 h265 时会沿阶梯往下试，停在能播的那一档。

需要真机确认的：这次取到的是 h265 档，如果黑屏或有声无图，请把 logcat 里 `Playback address attempt:` 与解码相关的行截给我。
