# 首页推荐与试播

当前正式基线 `0.1.8` / versionCode 49，Android 6+。`feature-home-feed-smooth` 的加载优化已随主线合入。

## 内容来源

默认「推荐」读取官方 App 域名下 `/reading/bookapi/bookmall/tab/v1/`，tab_type=16、bottom_tab_type=7；与官网固定分类列表分开。路径及卡片结构参考 [guoapp 公开实现](https://github.com/Xanerix/guoapp/blob/main/native/core/provider_hongguo_recommendations.go)，请求与解析在本项目独立实现。真人剧、漫剧按钮读取官方 App `/reading/distribution/category/landpage/v/` 分类推荐，分别使用 short_play/default 与 comic_series/comic_series，排序条件留空，支持服务器会话、offset、filter_ids。找剧页面使用独立的组合分类筛选。

2026-10-22 匿名只读探针已确认首批 3 部、下一批 6 部，其中 4 部新增；继续 offset=2 也有新增作品。推荐卡片可能包含全剧分集信息，试播仍明确播放该作品第一集，而非宣称官方预告。

客户端采用服务端 session_id 和递增 offset。实测 has_more、bottom_unlimited 的假值/缺省不能作为结束标记，因此有有效卡片时继续请求，交由 DramaFeedState 去重、重复批停止和每轮最多 100 页保护。游标与最后一批只在内存保存；请求完成但页面丢弃结果时，同一页重试复用结果。「换一批」继续后续批次，进入详情再返回保留列表与试播位置；每个入口各自保存推荐游标、本轮列表、分页及选中作品，切回时直接恢复列表并从头试播选中作品；换一批过滤重复作品，连续三批重复时停止并提示，不无限请求。分类推荐不等于已验证的个人兴趣推荐。

登录且账号验证通过时，仅在推荐请求中携带现有账号 Cookie 和设备标识；不发送给其他站点，不增加凭证文件。登录、退出、换账号时重建推荐客户端并清空原账号推荐及媒体缓存。已验证匿名读取和模拟账号请求隔离；尚未实机证明与手机兴趣一致。没有新增曝光、跳过、点赞或完播行为上报，不能宣称电视试播会训练官方推荐偏好。

## 遥控器与播放

- 顶部有推荐、漫剧、真人剧、换一批，当前来源高亮；三类入口均续取后续推荐。进入首页时输入焦点落在视频区；在第一行再按一次 ↑ 把焦点交回顶部导航（此前 `topHintShown` 从未被置位，这条路径实际走不到）。
- 视频区上下切换作品，确定打开暂停、观看全集、账户收藏操作栏。返回先关闭操作栏，再返回顶部导航。
- 在首页上没有任何操作满 20 秒自动进入全屏播放当前这一部，位置接着试播停下的那一秒，进入全屏后本集播完按「自动连播」接下一集正片。判断的是人有没有在这一页上操作：切剧、方向键、点按钮、触摸都会把这一轮重新开始；界面切到后台、这一部取址失败时取消。用户主动从全屏返回、按暂停或打开操作栏后，这一部不再被自动拽回；这份判断由 `MainActivity` 持有，跨首页界面保留，换到别的作品照常重新计时。计时与压制判断在 `core` 的 `AutoFullscreenGuard`，可独立测试。
- 进入全屏的过渡只动封面图：从卡片此刻的位置放大铺满（260ms，`AccelerateDecelerateInterpolator`），播放器不参与缩放与淡入——SurfaceView 的视频内容不跟随普通 View 变换，Media3 在 Android 6/7 上因缩放 PlayerView 出过现网问题（androidx/media #1664、#3070），本包 minSdk 23。封面按全屏尺寸单独取（`ArtworkLoader.requestBitmap`：这条取图不属于任何一页，换页不取消它。原先它走的是按页绑定的取图，`playEpisode` 建播放器前那次换页清理把它清掉了，于是进入全屏之后整段只剩一层黑）。触发前三秒先取好这张封面（`HomeFeedScreen.warmCover` → `MainActivity.warmTransitionCover`，与真正使用时同一个尺寸，否则对不上号），进入那一刻遮罩上就是现成的画面。过渡层挂在窗口内容层顶层，不被 `root.removeAllViews()` 清掉。
- 从进入全屏到画面真出现要读详情、签名播放地址、起解码器，实测一到三秒，这段时间不是一段黑：封面最迟 900 毫秒后这一层照样给出去并写明还在准备这一集，不把用户扣在「正在加载剧集」那种中间页上；画面没出来就不撤这一层（原先写死「2.5 秒后自行交出去」，而取址常常比它更慢，等于先撤掉封面、再对着还没有画面的播放器等）；取详情失败、播放失败或到 20 秒上限仍没有画面，立刻撤掉，让错误说明与播放界面的进度露出来。这些时刻本身在 `core` 的 `FullscreenHandoff`，可独立测试。
- 按比例显示画面，不裁切竖屏内容。准备好后收起底部状态提示，暂停、加载及错误时显示。
- 当前视频播放且缓冲达到 1.5 秒后，串行准备后面 3 部作品的播放地址及完整索引（先消费 32 KiB 并按需补齐完整索引，不等待整个 256 KiB 范围响应），保留上一部供回滑；相邻作品不足时提前补下一批卡片。缓存约 90 秒过期。
- 使用 Media3 DefaultPreloadManager 提前准备媒体源：下一部加载约 1.5 秒媒体样本，上一部加载约 1 秒，后两部提前选择轨道；共用一个 ExoPlayer 及其兼容组件，预加载总缓冲目标为 4 MiB。地址与索引就绪后即交给 Media3，不等待额外固定 1 MiB 预下载。换剧命中时将已准备的媒体源交给同一播放器并 prepare，不需要重新解析地址；仍可能有解码器切换等待，不保证所有电视与格式都无停顿。
- 若切到正在预加载的下一部，直接接续该任务，失败后再走前台请求；不会主动取消后立刻重复请求同一作品。切换其他作品或来源仍丢弃过期结果。
- 视频 HTTP 分段保持 512 KiB，但按实际收到的数据渐进读取和按绝对偏移解密，不等待完整分段下载；缓存包含完整已取 MP4 索引，避免大索引被播放器重复读取。
- 试播队列设置每个媒体末尾暂停，不自动跳下一部。再播、换剧或观看全集均由用户操作。
- 视频源移出预加载窗口后释放缓存；切换类型、退出、账号变化时清理旧源。HTTPS 连接池在后台关闭，避免界面线程网络异常。
- 试播没有 Library 保存和账户进度上传依赖；进入正式全集后才记录观看历史。推荐列表不进入收藏或历史数据库。
- 正常分类分页保留最多 72 部近期作品；缓存至多当前、上一部、后面三部。播放器缓冲目标约 6 MB。首页期间暂停自动更新检查。

## 首次进入与首集准备

- 增加按登录身份隔离、10 分钟过期的首屏元数据缓存，每个来源最多 30 部。只保存卡片和已核验的首集 ID/集数，不落盘播放 URL、服务端会话或凭据。分类首次详情核验得到的首集标识也回写到相应首屏缓存，之后无需重复读取该作品的完整详情。
- 缓存首屏是本地起始页，后续从 offset=0 建立新的服务端会话，并按已展示 ID 去重，不伪造或复用过期服务端 session。换一批继续真实游标获取；缓存过期、损坏或身份不符时不使用旧内容。
- 直接解析播放模型 video_list 数组中的 video_meta 与 encrypt_info，验证 URL、视频尺寸、编码和内容密钥；有可用项时省去 fallback_api GET，没有时保留原备用流程。匿名探针已交叉核对内嵌密钥与原备用响应一致，未打印地址或密钥。
- 首页索引准备在一次 256 KiB 分段响应中先消费 32 KiB，按索引实际大小继续读；不会为 32 KiB 以外、仍在本范围内的索引另开请求。超出范围时才补取，保留完整头、范围及样本校验。首次进入仍需实际推荐及播放信息；分类响应中的 episode 为布尔值，不能当首集序号，仍需可靠标识或详情核验。
- 匿名复测确认推荐及漫剧试播各使用 1 次播放模型请求、0 次备用接口请求，均成功准备视频索引。网络波动明显，探针不包含设备解码和首帧显示，不能作为电视端耗时保证。

## 验证

标准 core/app 单元测试、assembleDebug、lintDebug；页面测试覆盖 API 23、26。覆盖推荐卡片解析、分页重试与换批、账号请求隔离、来源切换、上下换剧复用预加载、下载中途切换及失败回退、慢速分段渐进读取、缓存与网络边界、实际 Media3 组件的注册/切换/清理、暂停/恢复和结束停留、进入全屏到画面出现这段等待期的时间安排（`FullscreenHandoffTest`：封面先到就用封面那一刻、封面不来最迟 900 毫秒给出暗底、画面没出来不撤层、失败与上限立刻撤、提示的两档时机）。接口替身及 Robolectric 不验证真实解码性能。

用户实机验收：默认推荐内容、换一批、漫剧/真人剧切换，停留几秒后上下换剧是否更快，试播结束是否停留，观看全集后返回位置，退出登录再登录是否更新内容，原有正式播放和云端进度是否正常。自动进入全屏这条路径仍需实机确认：进入首页焦点是否确实落在视频区、在第一行按 ↑ 能否回到顶部导航、没有操作 20 秒这个时长是否合适、连续切剧的过程中会不会误触发（每一次按键都应把计时重新开始）、封面展开的观感是否够顺、进入全屏到画面出现这一段还是不是一段黑（正常应先看到这一部的海报；海报没取到时最迟 900 毫秒后写明明还在准备这一集，而不是空着一层黑）、取址失败时错误说明与「立即重试」是否能直接看见（不被过渡层盖住）、进入全屏后是否接着试播停下的位置继续播、本集播完是否接下一集正片、从全屏主动返回后回到首页是否不再被自动拽回同一部。

版本码 39 修复共用 HTTP 客户端关闭跳转造成的内容请求 301：公开详情和视频允许跳转；推荐账号请求使用单独配置、禁止跳转的客户端，避免凭证转发。已实测两类推荐的后续批次、剧集详情、播放地址及 RemoteVideo.prepare，未操作模拟器或电视。

版本码 40 复用推荐响应中明确的 first_vid 或 video_list 中 vid_index=1 的标识及总集数，试播无需再请求一次详情；不使用未标记首集的普通 vid 代替。缺少可靠标识时回退完整详情，正式观看全集仍独立读取完整分集。试播专用 TrialClip 保存真实总集数，避免只取首集时误显示共1集。匿名探针将首集标识、总集数与官网完整详情交叉核对；分类推荐目前未提供这些标识，保留原详情流程。

公开内容客户端共享至多3条、空闲2分钟的连接池，各页面仍使用独立 dispatcher，关闭旧页面只取消其自己的请求，不误取消新页请求；账号推荐仍禁止跳转。此优化减少后续访问连接开销，首次进入仍受网络及播放解析耗时影响。

本轮只静态读取用户提供的官方 6.5.5.32 APK，确认存在 TTVideoEngine、DataLoaderHelper、短视频预加载准备与时机配置；没有运行官方包，也无法从组件存在推断其线上参数。播放器预加载按 [Media3 官方文档](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager) 独立实现。未进行官方与 TV 客户端的设备测速。`Home first-frame` 日志仅统计媒体源交给播放器至首帧的耗时，不包含先前推荐或播放地址请求。
