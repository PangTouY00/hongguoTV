# 红果账号同步

## 2026-10-21：0.9.5 修复电视确认后未保存登录态

用户反馈：手机扫码确认成功，电视二维码关闭后仍显示「未登录」。定位到 Android `OnDismissListener` 异步投递：成功分支在 `dismiss()` 后立即调用受 `busy` 保护的保存任务，此时关闭回调尚未清除 `busy`，保存任务被直接跳过。此前命令行验证覆盖认证和云端读取，没有覆盖这段 Android 弹窗交接，因此不能作为电视状态保存已验证的证据。

修复：程序主动关闭二维码时先解除关闭监听，同步结束二维码操作，再启动加密保存任务；关闭回调不能取消或改变后继保存任务。取消、过期、确认保存各有明确状态，保存失败显示独立错误弹窗，不静默停留在未登录。

产物：`outputs/hongguotv-0.9.5-login-save-fix-20261021-debug.apk`，versionCode 14，同一本地签名，可覆盖 0.9.4。验证：现有 99 项 core 测试、Android Debug 构建和 lint 通过；用户已确认 0.9.5 电视扫码后可以登录；重启恢复仍待核对。本轮没有重新请求验证码或新账号授权。

用户明确授权后进行一次短信测试：官网返回错误码 1105，要求滑块验证，**未发出新短信**。不绕过验证，不重复请求短信。用户用红果 App 扫码并确认后，已实际验证：`officialWebLogin=true`、`mobileAccountVerified=true`、`cloudHistoryLoaded=true; items=50`。同一个官网会话能够验证真实红果账号并读取最近 50 部云端观看记录。测试进程退出后不保留登录凭据，电视需单独扫码。

电视账号页新增官方扫码入口，短信切换到官网流程；取消或二维码过期会结束等待。即使官网确认成功，也必须验证真实红果账号资料后才保存登录态；云端记录读取已验证，电视写入后的手机端续播仍需安装后核对，不将其宣称为已完成双向验收。

验证：99 项 JVM 测试及 Android Debug 构建通过。涵盖官网短信参数、CSRF 会话保持、扫码确认跳转及拒绝跨站跳转。真实账号登录、手机记录读取已完成扫码实测；不把单元测试当作上传后手机续播已验证。

交付版本：`outputs/hongguotv-0.9.4-official-login-20261021-debug.apk`（versionCode 13，沿用此前本地开发签名，支持覆盖安装）。Android lint：0 errors、30 warnings，签名与版本元数据校验通过。设置 → 红果账号 → 使用红果 App 扫码登录。保留全部搜索、播放兼容修改和本地加密保存登录态。过期可刷新二维码；短信遇到滑块可直接改用扫码。

## 历史调查（2026-09-22，以下为当时结论）

用户目标：用本人抖音账号登录红果，在电视端同步红果收藏、观看历史及续播位置。保持用户只安装 APK、无需自行部署服务。

## 当前结论

本轮没有实现红果登录或云端同步。缺少经过验证的红果用户授权、账号映射、收藏和进度读写接口；普通抖音 OAuth 授权不能作为这些权限已获授予的证据。不得将头像或昵称获取成功标记为“红果已登录/已同步”。

- 当前客户端 `ContentRepository` 使用游客内容请求，搜索参数 `user_is_login=0`；`Library` 的收藏和进度在本机 SharedPreferences，没有平台账户会话。
- 检查红果官网首页、首页直接引用的三个业务脚本，未找到登录入口或账户同步实现。范围仅限这些公开资源，不能据此推断平台没有内部或合作接口。
- [抖音 SDK 概述](https://open.douyin.com/platform/resource/docs/develop/summarize/sdk) 描述抖音授权和获取公开用户资料；更多数据能力需对应申请。未找到明确开放红果收藏和观看进度的 scope。
- [抖音网站 OAuth 文档](https://open.douyin.com/platform/resource/docs/develop/permission/web/oauth2) 要求注册开发者配置 ClientKey / ClientSecret，通过授权码交换令牌，并提示应用密钥放在客户端不安全。项目当前未配置该应用的平台注册凭据，不能挪用红果官方 App 的身份和应用密钥来声称已授权。
- 本轮没有收集用户密码、验证码、Cookie 或令牌，没有登录或改动用户的平台收藏和进度。

## 接通所需证据

1. 平台允许此应用使用的授权方式、ClientKey、应用包名/签名配置，以及是否必须有服务端保管应用密钥。只有可安全运行于客户端的授权流才能直接保持纯 APK；服务端必需时必须另行明确托管方案，不能将密钥塞入 APK。
2. 抖音身份到红果账户的受支持映射及用户数据授权范围。
3. 收藏分页、历史与精确播放进度读取接口，含字段定义、权限错误及会话过期行为。
4. 先完成本人真实账号只读验证，再接入收藏和进度写回。双端冲突按更新时间与明确的播放会话处理；不能简单取最大集数，避免覆盖用户重新观看较早集的意图。
5. 退出、过期、换号测试；按平台账号隔离缓存，保留并区分既有本地游客记录，避免串号。

账号功能依赖上述平台接入条件，不是只增加一个 UI 登录按钮即可交付。新版本中的“手机输入”二维码仅发送局域网搜索词；“版本与更新”二维码仅打开 GitHub Release 页面，都不是红果账号登录。
